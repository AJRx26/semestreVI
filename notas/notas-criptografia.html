4.1. STRIDE

  • STRIDE es un modelo de amenazas, utilizado para ayudar a razonar y encontrar amenazas a un sistema.
  • Spoofing: Suplantar la identidad en redes informaticas haciendose pasar por una persona, entidad o sistema de confianza para engañar a la victima. Se puede mitigar por firmas digitales, contraseñas, etc. -> Autenticidad
  • Tampering: Alterar, manipular o interferir con algo sin autorización, generalmente con el fin de causar daño, obtener beneficios ilegales o comprometer la integridad de un sistema, proceso o evidencia. Usa la tecnologia de hash para mitigarlo. -> Integridad
  • Repudation: El acto de negar, por parte de una persona o sistema, haber realizado una acción, transacción o comunicación especifica. -> No repudio
  • Information disclosure: Acceso no autorizado o la revelación inadvertida de datos sensibles, confidenciales o privados a personas, sistemas o entidades que no deberian tener acceso a ellos. -> Confidencialidad
  • Denegation of service: Hacer que un sistema, servicio o red sea inaccesible para sus usuarios legitimos. -> Disponibilidad
  • Elevation of privileges: Otorgar permisos a usuarios que no deben de tener dichos permisos. -> Autorizacion

4.4. Hashing

  • 3**2 = 9 -> Biyectivas
  • 22 % 2 = 0 ->
  • El hashing es uno de los elementos principales de la seguridad criptografia. Involucra el concepto de una funcion de una sola via y huella digital.
    • Una funcion hash solo funciona si cumple con los siguientes requisitos:
      1. Producen valores unicos y repetibles, es decir, son deterministas para cada entrada.
      2. El valor de salida no da ninguna pista (o patron) con respecto a la entrada que lo produjo.
  • Algunas funciones de hash son mejores que otras cumpliendo las propiedades antes mencionadas.
  • Buenas: SHA-256, SHA-512
  • No tan buenas: MD5, SHA-1. Estas no deberian ser usadas por sus vectores de seguridad.
  • Solo funciona con cadenas binarias

4.4.1. Cifrado vs Hashing

  • El cifrado permite tener confidencialidad en los mensajes, pero ayuda a verificar la interidad de los mismos.
  • Confidencialidad: Solo las personas autorizadas pueden leer el mensaje.
  • Integridad: Las personas no autorizadas no pueden cambiar el contenido del mensaje sin que dicho cambio pueda ser percibido.
  • Solo porque un mensaje este cifrado (no pueda ser leido) no significa que no pueda ser alterado, incluso de formas que no tengan sentido despues de cifrar.

4.4.2. DIGESTS

  • Su traduccion seria “resumen”

  • Este resumen puede utilizarse como medida para verificacion de tampering (alteraciones de informacion), utilizadas en analisis forense.
  • En una transmision la idea es transmitir el mensaje junto con su digest, para verificar que haya llegado sin alteraciones.

4.4.4. Funciones de hash

  • Una funcion de hash toma un contenido de cualquier tamano(hasta vacio) y siempre produce un numero de un tamano fijo.
  • Por ejemplo, MD5 produce una salida de 16 bytes
  • Este tamano tiene una relacion con la seguridad de la funcion entre mas pequenos es peor.
  • Dominio -> Codominio
  • Una vez mas, las propiedades que una funcion de hash debe de cumplir son:
    • El mismo documento siempre produce el mismo digest.
    • El digest parece aleatorio, si tienes el digest eso no te da pistas del documento de entrada.
    • Idealmente cada documento con contenido diferente deberia tener un digest diferente (lo cual en realidad no es posible).
  • Los digests son como huellas digitales: si tienes al sujeto se puede verificar que sea quien dice ser mediante su huella digital.
  • Sin embargo, si solo tiene la huella digital no es facil determinar el sujeto que la posee.
  • Es facil calcular el digests de un documento, pero si tiene solo el digest es muy dificil determinar el documento que lo produjo, entre mas dificil mejor.
  • Por esta razon son llamadas funciones de una sola via, se puede ir de entrada a la salida pero no al reves.

4.4.5. Hashing

  • En computacion, el termino funcion de hash casi siempre se refiere a una funcion criptografica.
  • Sin embargo, el termino es general
  • Por ejemplo: Una funcion hash que establece si un numero es par o impar. Esencialmente, las funciones hash relaciona elementos de un dominio muy grande, con elementos de un codominio relativamente pequeno.
  • El tamano del codominio depende de la funcion de hash, por ejemplo, ya se dijo que MD5 genera digest de 16 bytes. Cual es el tamano del codominio para MD5?
  • SI se considera un numero muy grande de documentos de entrada es posible que muchos de ellos produzcan el mismo hash.
  • Dado lo anterior, las funciones de hash tienen perdida. Se pierde informacion de la fuente al digest.
  • Que tenga perdida es importante, de lo contrario habria una forma de regresar del digest al documento original.
  • Considerando de nuevo la funcion par
  • Cualquier numero puede dar como resultado 0 (par) o 1 (inpar)
  • Seria posible saber, dado un valor 0 o 1que numero produjo dicho resultado
  • Esta funcion tiene todas las propiedades: tienen perdida, comprime la entrada y es consistente ya que dada la misma entrada siempre produce la misma salida.
  • Las propiedades de consistencia, compresion y perdida son comunes en cualquier funcion de hash pero no suficientes para ser seguras o criptograficas.
  • Se requieren las sig. propiedades:
    • Resistencia de preimagen.
    • Segunda resistencia de preimagen.
    • Resistencia de colisiones.
  1. Resistencia de preimagen
    • Una preimagen es el conjunto de entradas de una funcion de hash que producen, en el caso de par o impar, una preimagen son todos los numeros pares que den valor 0.
    • Una preimagen de una funcion de hash H y un valor de hash k es el conjunto de valores x por el cual H(x) = k
    • Al tener un digest, existe un numero infinito de documentos que produjeron dicho digest.
    • Eso no quiere decir que dado un digest sea facil encontrar un elemento de la preimagen
    • La resistencia de preimagen es basicamente: si tengo un digest y no se como se obtuvo, no pudo ni siquiera encontrar un elemento en la preimagen sin realizar una cantidad ridicula de trabajo computacional.
    • Intratable -> Se puede resolver, pero cuesta demasiado
    • No computable -> No se puede resolver con una computadora
    • Idealmente, los elementos de la preimagen deberian estar muy separados entre ellos y no tener un espaciado predecible
    • El hecho de que las funciones de hash tengan perdida ayuda a la resistencia de preimagen
    • Si una funcion de hash tiene buena resistencia de preimagen, los ataques en este sentido seran aleatorios o bien consistiran en enumeraciones muy largas (fuerza bruta) hasta encontrar una coincidencia, lo cual no es computacionalmente tratable.
    • Al proceso de intentar encontrar un elemento de la preimagen dado un valor de hash se le llama invertir el hash
    • Encontrar un inverso deberia ser muy dificil.
  2. Segunda resistencia de preimagen
    • Si tu tienes al menos un documento que produce un hash conocido, sigue siendo muy dificil encontrar otro documento que produzca el mismo hash.
    • Esto funciona porque no existe patron repetible en los elementos de la preimagen.
  3. Resistencia a colisiones
    • Significa que es dificil encontrar dos entradas que produzcan el mismo hash y garantiza que sea computacionalmente inviable encontrar dos entradas diferentes que produzcan el mismo valor hash.
    • No un hash especifico sino cualquier hash.
    • Es mas facil encontrar una colision en un hash cualquiera que encontrar un elemento de la preimagen de un hash dado.
    • Propiedad avalancha: El valor de hash cambia drasticamente y de forma impredecible, un minimo del 50% de los bits del hash deberia ser diferente.

4.4.6. Seguridad en funciones de hash

  • Hash es usado para el almacenamiento de passwords, pero siguen teniendo problemas de seguridad, el mas comun es la situacion donde dos usuarios usen la misma contrasena y por tanto, genere el mismo hash, existen muchas soluciones (A2F, Token fisico, etc) pero la mas recomendada es agregqar un salt.
    • Salt: Es un valor usualmente aleatorio que se debe de agregar al password antes de aplicarse a la funcion de hash. Debido a la propiedad de avalancha, con el salt el hash resultante cambiara drasticamente. Y como son aleatorios, es poco probable que dos usuarios con la misma password tenga el mismo salt.

4.5. Cifrado simetrico

  • Cifrado que usa la misma llave para cifrar y descifrar, la llave es un secreto compartido.

4.5.1. AES

  • Advanced Encryption Standard
  • Lo utiliza TLS (HTTPS) y funciones de cifrado de sistemas de archivos de un OS.
  • AES es un cifrador de bloque, cifra por bloques de 16 bytes, si no cumple con los 16 bytes se debe de agregar un padding (datos de relleno).
  • Tambien puede cifrar un byte a la vez, esto se concoe como cifrado de flujo y no necesitan padding.
  • En general, es mas eficiente cifrar bloques que en flujo.
  1. Modos de operacion de AES
    1. ECB - Electronic Code Book
      • Cualquier texto plano de 16 bytes tiene 16 bytes correspondientes de salida.
      • Cada bloque es tratado independientemente, esa es su debilidad.
        • Puede generar un ataque de texto plano escogido, que se basa en tener muchos mensajes de estructura parecida para enganar con un mensaje falso con una respuesta predecible.
      • Parametros: Texto plano y llave.
    2. CBC - Cipher Block Chaining
      • Despues de cifrar el bloque aplicar una funcion XOR con el siguiente bloque en texto plano, el resultado se cifra y se guarda ese bloque. Para descifrar se tiene que invertir el proceso.
      • Para el primer bloque a cifrar, se utiliza el IV dado que no hay un bloque anterior para hacer XOR, el IV debe de ser del mismo tamano del bloque (16 bytes).
        • Parametros: Texto plano, llave e IV
        • Debe de tener su respectivo padding.
    3. CTR - Counter Mode
      • No requiere de padding
      • Genera un key stream de cualquier longitud a partir de una llave AES de al menos 128 bits (16 bytes), luego aplica XOR para combinarlos.
      • CTR incrementa el contador en uno y asi sucesivamente. Si el texto plano no es multiplo de 16, los ultimos 16 bytes del key stream se truncan para corresponder al texto.
      • Al IV se le llama nonce.
      • CTR puede cifrar de forma independiente.
      • Parametros: key, nonce, texto plano.

4.5.2. Seguridad en cifrado simetrico

  • Para tener un cifrado seguro y efectivo se necesita:
    1. Cifrar el mismo mensaje de forma diferente cada vez que se haga, aunque se use la misma llave.
    2. Eliminar patrones predecibles entre los bloques. (Maleabilidad entre bloques)
  • Para resolver el primer problema, se utiliza un vector de inicializacion (IV), el cual es una cadena aleatoria externa al texto plano y la llave. El IV es publico ya que solo hace que los mensajes no sean repetibles y no generar patrones.
  • Nunca debe reusarse el mismo IV
  • Existen ataques donde si conoces el texto plano y el IV (suponiendo que lo reutilizan) puedes obtener el key-stream.

  1. Message Authentication Code (MAC)
    • Un cifrado puede ser alterado de formas que tenga sentido.
    • Un MAC es cualquier codigo o dato transmitido junto con el mensaje que puede ser evaluado para determinar si el mensaje fue alterado.
    • Usualmente se utiliza un hash como
    1. MAC, HMAC, CBC-MAC
      • Un MAC seguro no solo es codigo (hash) tambien debe incluir una llave.
      • Una llave MAC no esta relacionada con el cifrado
      • Sirve para asegurar que el codigo de autenticacion de mensaje solo puede ser computado por las entidades que conocen la llave.
      • No se debe de asumir que el atacante no conoce la funcion de hash, recuerda que una buena seguridad significa…
      • MAC protege la integridad del mensaje
      • Un atacante sin la llave no debe poder alterar el mensaje sin que se pueda detectar.
      • Mientras la llave se mantenga privada, el MAC
      1. HMAC
        • Hash-based Message Authentication Code
        • Es basicamente un hash keyed
        • Las funciones de hash son deterministas, dada la misma entrada siempre se produce la misma salida.
        • Solo agregar al inicio o al final
        • H(K XOR opad + H((K XOR ipad)+ text))
          • H es la funcion de hash
          • K es la llave que debe de cumplir ciertos requisitos
          • text es cualquier binario que representa el contenido de entrada
          • opad e ipad son dos valoresi
          • B es el tamano del bloque de H (128 bytes)
            1. Si K es mas corto que B, entonces a K se le tienen que agregar ceros de padding hasta ser de longitud B.
            2. Si K es mas largo que B, entonces K se reduce aplicando H a K, osea H(K)
            3. Si se aplico 2 y la llave quedo muy corta, entonces se aplica 1
          • Si se aplica lo anterior, siempre se va a tener una llave de longitud B.
          • ipad se define com el byte 0x36 repetido B veces
          • opad es el byte 0x5c repetido B veces
          • Los pads parecen arbitrarios pero tienen un sentido de seguridad matematico que ayuda a mitigar
        • Primero computas
      2. CBC-MAC
        • Similar a AES-CBC
        • Recordar que CBC es Cipher Block Chaining
        • Un MAC a menudo se le llama “tag” (mensaje) del mensaje
        • Es info extra que se asocia al principio del contenido
        • En notacion matematica un tag se denota a menudo como t
        • Asi, un MAC sobre un mensaje m1 produce un tag t1
        • El par (m1, t1) es transmitido al receptor para ser verificado
        • AES solo puede cifrar 128 bits de bloque a la vez.
        • AES-CBC encadena la salida de un bloque cifrado con el siguiente bloque.
        • Si se altera uno se alteran todos los bloques siguientes.
        • El ultimo bloque de CBC es en si un MAC.
        1. MAC Prepend Attack
          • Es posible mandar un mensaje manipulado y hacer que parezca que es el mensaje M1 o M2, suponiendo que esten generados por la misma llave.
          • M3 es una mezcla de M1 y M2.
          • No es necesario conocer la llave de MAC.
          1. Proceso de ataque, anteponiendo M1 a M2
            • Recuperar el primer bloque de M2, denominado M21 (como es AES se toman los primeros 16 bytes)
            • Recuperar el resto de bloques de M2, denominado M2r
            • Obtener M’2 = t1 XOR M21
            • M3 = M1 + M’2 + M2r (+ significa concatenacion)
            • Con esto t3 = t2
            • Basicamente lo que hace el atacante es reemplazar el primer bloque de M2 por uno manipulado.
            • La victima vera todo el mensaje M1 completo (con su padding), un bloque que se vera posiblemente corrupto y el mensaje M2 sin su primer bloque.
          2. Soluciones
            • Agregar siempre la longitud del mensaje al inicio. Esto ayduara a corroborar si hay información extra.
            • Si se cifraron los datos usando AES-CBC, no se debe usar la misma llave para cifrar ni para obtener el MAC.
            • El IV debe ser diferente a un valor de cero.
    2. Cifrado y MAC
      • Encrypt-Then-MAC: El MAC se aplica al texto cifrado.
      • MAC-Then-Encrypt: Se aplica al texto plano, luego se cifra el texto plano junto al MAC.
      • Encrypt-And-Mac: Se aplica MAC sobre el texto plano, pero no se cifra el MAC, solo el texto plano.
      • Recomendación: Siempre usar Encrypt-Then-MAC.
      • El ataque de padding oraculo a CBC funciona en MAC-Then-Encrypt.
  2. Firmas digitales
    1. RSA
      • Dado que los MAC usan llaves simetricas, si se compromete la llave puede ambos lados estan en riesgo de spoofing (usurpación de identidad).
      • Las firmas intentan mitigarlo mediante criptografia asimetrica. Ya que nos existen llaves “compartidas”.
      • La llave publica solo se puede descifrar con la llave privada y vise-versa.
      • Si se cifra con la llave privada, puede ser descifrado por la llave publica.
      • Autenticidad en reversa: El receptor no sabra de quien es el mensaje pero el emisor sabe que solo podra ser procesada por la entidad autorizada.
      • Existen muchos problemas con el cifrado asimetrico (RSA), es ineficiente para archivos grandes, no viene comprobación de integridad y solo puede procesar archivos del tamaño de modulo (2048 bits).
      • Para solucionar eso, se hace lo siguiente: Cifrar el hash del mensaje, dando tanto integridad como autenticidad.
        1. Calcular el hash del mensaje.
        2. Cifrar el hash mediante la llave privada, este hash cifrado es la firma del emisor.
        3. El receptor calcula el hash del mensaje, descifra la firma mediante la llave publica y comprueba que coincidan ambos hashes.
      • La firma debe de aplicarse siempre al texto plano, nunca al cifrado.
      • El cifrado con la llave publica es confidencialidad.
      • El cifrado con la llave privada es autenticidad.
      • El padding para firmas RSA es PSS.
      • Es comun usar tecnicas asimetricas al inicio de la comunicación para el establecimiento de confianza e intercambio de llaves simetricas. Despues todo el proceso se hace con llaves simetricas.
    2. Curvas Elipticas
      • Alternativa a RSA
      • Se usa para firmas digitales y el intercambio de llaves.
      • Se usa ECDSA para firmar.
      • Parametros:
        • Tipo de curva (P-384 - SECP384r1)
    3. Transporte de Llaves RSA
      1. Alguna de las partes genera la llave simetrica. (probablemente el servidor)
      2. Se cifra la llave simetrica con una llave publica.
      3. La otra parte tiene una llave privada.
      4. Se transmite la llave cifrada y se descifra.
      5. Seguridad hacia delante (Forward Secrecy)
  3. Certificados
    • Prueban la pertenencia de las llaves publicas.
    • Modelo PKI (Public Key Infraestructure)
      • Un registro global donde se almacenaban las llaves publicas asociadas a una entidad.
      • La llave publica se compartia.
      • No era escalable.
    • Un certificado solo son datos, incluyen:
      • Una llave publica
      • Metadatos del propietario de la llave (identidad del propietario de la llave, identidad del issuer, fecha de expiración, numero de serie, etc)
        • La identidad del propietario puede ser un nombre, email, URL, etc.
      • Firma digital sobre todo el contenido del certificado
      • Firma por la entida de confianza (issuer)
    • Se comparten los certificados en lugar de las llaves publicas.
    • Una entidad quiere un certificado:
      1. Genera su par de llaves
      2. La entidad de confianza recibe la llave publica y genera el certificado
      3. La entidad de confianza firma el certificado con su llave privada
    • Para evitar que un agente malicioso use un certificado que no es suyo, se usa el proceso reto-respuesta (challenge-response).
      • Se basa en pedirle que firme un mensaje con la llave privada y verificarla con la llave publica del certificado. Si coincide, entonces si puedes confiar.
    • Protocolo reto-respuesta
      1. El cliente recibe la llave publica del servidor (certificado).
      2. El cliente le manda un reto al servidor.
      3. El cliente le pide al servidor que firme el dato.
      4. El servidor firma el dato y regresa la firma.
      5. El cliente comprueba la firma con la llave publica.
    • Quien firma es quien quiere ser autenticado
    • Siempre se firma con la llave privada
    • Se verifica la firma con la llave publica
    • La firma tiene dos propiedades de seguridad
      • Integridad
      • Autenticidad
    • Al issuer se le llama Certificate Authority (CA)
      • Estos tambien tienen sus propios certificados con nombre de identidad y su llave publica.
    • Certificados:
      • Metadatos del propietario (subject)
      • Metadatos de la propiedad de confianza (CA/issuer)
      • Llave publica
      • Firma del CA
    • El certificado no tiene nada que ver con el cifrado, ni con la protección del canal en general.
    • El certificado no se usa directamente para autenticar, eso se hace con firmas digitales.
    • El certificado solo es un mecanismo para confiar en la llave publica
    • Criptografia asimetrica
      • Firmas digitales
      • Intercambios de llaves
    1. Revocación de certificados
      • Si la llave privada de un certificado creado por un CA es comprometido, el CA debe hacer saber a los demas que ya no es confiable.
      • Dado que no se puede tener un sistema offline de revocación, existen dos alternativas:
        • Tener un componente en tiempo real
        • No se puede actualizar en tiempo real
      • Un ejemplo es OCSP (Online Certificate Status Protocol)
        • Revisa el estatus del certificado en tiempo real
        • Tambien revisa CRL’s (listas de certificados revocados)
      • La recomendación final siempre sera proteger las llaves privadas, de preferencia en un lugar offline y/o con permisos minimos con un cifrado adicional.
      • Los certificados deben tener un tiempo de vida relativamente corto.
    2. Ataques de repetición
      • Un mensaje legitimo es utilizado por un atacante tiempo despues cuando el mensaje ya no es valido.
      • Soluciones:
        • Se agrega un nonce (numero aleatorio) para hacer seguimiento de mensajes recibidos.
        • Usar timestamp (fecha del mensaje) para rechazar mensajes demasiados viejos. Aunque es necesario una ventana de tiempo para lidiar con retrasos.
        • Combinar timestamp y nonces aleatorios, rechazar mensajes muy viejos ademas que tengan el nonce repetidos dentro de la ventana de tiempo permitida.

4.8. Combinación de metodos simetricos con asimetricos

  • Intercambio de llaves (simetricas)
  • RSA cifra llaves AES compartidas en la comunicación

4.8.1. Agree Upon Transmission

  • Transmite un solo flujo de bytes con todos los datos necesarios concatenados
  • Sirve para transferir un solo mensaje
  • Tienes: llavesaes, llavemac, iv cifradas con la llave publica
  • Llave publica del receptor (viene con el certificado)
  • Cifras las llaves con la llave publica (RSA)
  • Firmar llaves planas
  • Cifras el mensaje con la llaveaes e IV
  • Calcular el HMAC sobre todos los datos
  • De sesiones cortas
  • Es practico para mensajes largos
  • Llave AES, IV y llave MAC cifradas con la llave publica del receptor
  • La firma digital sobre la concatenación (no cifrada) de la llave AES, IV y llave MAC.
  • Los bytes del mensaje transmitido, cifrados con la llave AES e IV.
  • El HMAC sobre la transmisión utilizando la llave MAC.
  • Descifra mediante su llave privada, obtiene la llave AES, IV y MAC
  • Verifica la firma digital, mediante el certificado del emisor.
  • Calcula HMAC de 1, 2 y 3 con la llave MAC y lo compara con 4.
  • Descifra 3 mediante la llave AES y el IV.

4.8.2. Llaves de sesión

  • Se usa una sola vez y se descarta permanentemente, es decir, son efimeras.
  • Llaves para el cifrado en masa
  • CIfrado en masa: Se cifra una gran cantidad de datos.
  • Payload: cargo util
  • Son faciles de crear
  • Se pueden derivar de un secreto base usando funciones de derivación de llaves.

4.8.3. Diffie-Hellman DH

  • Criptografia asimetrica
  • Una variante es con curvas elipticas ECDH
  • Intercambia parametros publicos para computar simultaneamente la misma llave en ambos lados, esto se llama Key Agreement
  • Primero crea un par de numeros matematicos, uno privado y publico. Esto para cada participante.
  • Ambas partes intercambian sus numeros publicos.
  • Con el numero publico externo y el numero privado local se genera la misma llave compartida en ambos lados.
  • El resultado es una llave simetrica o un dato que permite derivar una llave simetrica.
  • Requiere comunicación bidireccional.
  • Los parametros de DH deben ser iguales
    • Tamaño de la llave (2048)
    • Generador (2, 5)
  • Se recomienda usar HKDF para derivar la llave
  • DH no tiene autenticación integrada
  • Una o ambas partes deben de firmar publicos intercambiados.
  • Son preferiables para el transporte de llaves antes que RSA.
  • Principalmente porque ofrecen “Confidencialidad hacia delante” (Forward Secrecy) dada la naturaleza de las llaves efimeras, si una llave es comprometida, no se revela nada acerca de comunicaciones previas.
  • A veces para establecer un canal de confianza necesitas transmitir datos con poca protección (pueden ser manipulados)
  • Eventualmente se llega a tener un canal que se cree protegido (ya se hizo bien el intercambio de llaves)
  • Mientras tanto se fueron calculando hashes de todos lo que se transmitio
  1. Autenticación con DH y ECDH
    • El intercambio de llaves requiere una llave publica RSA o ECDSA, con su certificado firmado. Se usan para establecer identidad de cada parte, firmando info efimera durante el proceso de generación.
    • Ademas se agrega challenge-response.

4.8.4. Protocolo Reto-Respuesta

  • “Yo te envío un reto aleatorio. Si puedes responder correctamente, demuestras que posees la llave privada.”
  • Paso 1: Alice envía su certificado
    • Alice → Bob
    • El certificado contiene:
      • Nombre Alice
      • Llave pública Alice
      • Firma del CA
    • Bob verifica:
      • Certificado válido
      • No expirado
      • Firmado por una CA confiable
  • Paso 2: Bob genera un reto
    • Bob crea un número aleatorio:
    • Reto (Nonce) = 93741852 (Porque debe ser imposible predecirlo.)
  • Paso 3: Bob envía el reto
    • Bob → Alice (93741852)
  • Paso 4: Alice firma el reto
    • Alice calcula: Firma = Sign(93741852) usando la llave privada de Alice.
    • Con RSA: Firma = Retod mod n
  • Paso 5: Alice responde
    • Alice → Bob (Firma)
  • Paso 6: Bob verifica
    • Bob utiliza: Llave pública de Alice obtenida del certificado.
    • Verifica: Verify(Firma, Reto)
      • Si la verificación es correcta: Sólo alguien con la llave privada pudo generar esa firma.

4.8.5. Ramsonware

  • Software que cifra archivos y se rehusa a liberarlos hasta que le pagues al extorsionador que esta detras de todo.
  • El atacante genera dos llaves permanentes.
  • El atacante hardcodea la llave publica permanente en el ramsonware
  • Cuando el malware se activa se crean un par de llaves locales
  • Se cifra la llave privada local con la llave publica permanente y se elimina la versión plana.
  • El malware cifra los archivos usando AES, cada archivo cifrado tiene una llave diferente que es cifrada con la llave publica local, solo pueden ser descifradas por la llave privada local.
  • Cuando se haga el pago, el malware envia la llave privada local cifrada al servidor CC
  • Con la llave privada permanente se descifra la llave privada local y se reenvia a la victima
  • Ahora se pueden descifrar las llaves AES.
  • La llave privada permanente nunca es revelada.

4.9. Cifrado simetrico avanzado

4.9.1. Cifrado autenticado con datos adicionales (AEAD)

  • Authenticated Encryption with Aditional Data
  • Proveen autenticidad, integridad y confidencialidad.
  • Reemplazan a los MAC’s
  • Es mejor usar AEAD antes que los MAC
  1. AES-GCM (Galois/Counter Mode)
    • Permite cifrar y autenticar con una sola llave
    • IV de tamano de 12 bytes
    • No usa padding
    • Recomendable usar junto a Scrypt o HDKF
    • Datos adicionales no se cifran pero deben de autenticarse mediante la llave derivada.
    • Al terminar el proceso se obtiene un tag.
    • No usar IV 0
    • Segementar lo que transmites
    • Un IV difeente para cada segmento
    • No transmitir mas de 64 gb con la misma llave
    • No usar el mismo par de llave e IV (nonce)
    • GCM usa IV’s de 12 bytes, a los 4 bytes restantes se les agrega un padding de ceros, para tener un contador de 16 bytes.
  2. AES-CCM
    • Basado en CBC
    • Tag computado similar a CBC-MAC
    • IV de entre 7 a 13 bytes
    • Puede cifrar datos mayores a 64 GB
    • No es tan eficiente como GCM
  3. Chacha20-Poly1305
    • Combina un cifrador de flujo (ChaCha20) con un algoritmo de MAC (Poly1305)
    • No se han encontrado vulnerabilidades en este algoritmo
    • Suele ser mas rapido que AES
    • Es verdaderamente de flujo
    • Usa un IV de 12 bytes.

4.9.2. Kerberos

  • Es un protocolo muy conocido basado en cifrado simetrico para autenticación.
  • Es un intermediario entre dos entidades que se desean comunicar siendo un tercero de confianza.
  • Si el cliente se autentica primero al servicio de Kerberos, le permite el acceso a los servicios que esten conectados a Kerberos
  • Componentes basicos:
    • Servicio de autenticación
    • Servidor de tickets

4.10. TLS

  • HTTPS basicamente encapsula trafico HTTP dentro de TLS.
  • TLS permite a un cliente verificar la identidad de un servidor y establecer una sesion segura y mantener llaves compartidas de cifrado.
  • Las llaves se mantienen secretas incluso si un atacante intercepta el trafico.
  • Usa PKI
  • Si una entidad quiere TLS requiere de un certificado X.509

4.10.1. Certificados X.509

  • Su proposito es ligar la identidad de un subject a una llave publica bajo la firma de un issuer.
  • Tiene 3 posibles campos, pueden tener varios niveles de sub-campos.
    • Certificate
      • (a) Version Number
      • (b) Serial Number
      • (c) Signature Algorithm ID
      • (d) Issuer Name (describe la identidad pretendida)
      • (e) Validity Period
        • i. Not Before
        • ii. Not After
      • (f) Subject Name (describe la identidad pretendida)
      • (g) Subject Public Key Info
        • i. Public Key Algorithm
        • ii. Subject Public Key
      • (h) Issuer Unique Identifier (optional)
      • (i) Subject Unique Identifier (optional)
      • (j) Extensions (optional)
    • Certificate Signature Algorithm
    • Certificate Signature
  • La version 3: Incluye el campo adicional “Subject Alternative Name”
  • Una vez identificados el issuer y el subject, los campos restantes son la llave pública del subject y la firma del contenido del certificado.
  • Los certificados vienen firmados por un issuer.
  • Si quiero comprobar un certificado tambien necesito el certificado del issuer (la llave publica del issuer).
  • Se necesita una cadena de certificados, hasta llegar al certificado raiz (autofirmado).
  • Si quieres engañar a alguien para entrar a un sitio web falso que necesitas?
    • Sitio web con dominio casi igual.
      • IDS/IPS
      • Educar al usuario
  • Si alguien quiere tener un certificado, necesita un Certificate Signing Request (CSR) y enviarselo al CA. Esta peticion tiene todos los campos que un certificado X.509 solo que sin los campos del issuer.
  • El CA usa su porpio certificado y llave privada para generar el certificado con los campos faltantes. El issuer del certificado debe ser igual al campo de subject del certificado de quien firma.
  • Cuando los campos son rellenados el CA firma el certificado con su llave privada.
  • El CSR solo tiene la llave publica.
  • Los certificados estan en formato DER o PEM.
  • Prueba de posesion: El CSR esta firmado por la llave privada del subject.
  • En un certificado auto-firmado el subjec e issuer son iguales.
  • Generar una llave privada (2048 bits) y el CSR (durante su creacion se extrae la llave publica y se agrega a la peticion).
  • El issuer genera el certificado firmandolo con su llave
  • Con este certificado se pueden firmar nuevos certificados.
  • Para los nuevos certificados se deben de crean sus respectivas llaves.
  • Con los certificados del CA, se pueden generar certificados asociados a los nuevos CSR.
  • Envenenamiento de DNS
    • Solo funciona si usas http o si se tiene una llave privada asociada a la cadena de certificados.
      • Se mitiga para http con redireccion hacia https
    • Por que no funciona con https?
      • Por la comprobación de certificados
  • Yo tengo un certificado
  • Como lo avala un tercero?
  • Una cosa es que se compruebe que la entidad es la propietaria verdadera del certificado
  • Y otra es que el certificado sea confiable.

4.10.2. TLS 1.2

  1. Handshake
    1. Comienza con un cliente enviando un mensaje hello al servidor. Este mensaje contiene info de configuración, tipo nonce. Tambien esta la lista de Cipher Suites.
      • El objetivo es ponerse de acuerdo en cuanto al algoritmo y protocolos criptograficos a usar. La Cipher Suite da opciones.
      • La seguridad depende del Cipher Suite usado.
    2. El servidor recibe un hello cliente, escoge uno de los cipher suites propuestos del cliente. Cuando escoge uno, envia una respuesta con la siguiente info:
      • Hello con nonce
      • Certificado
      • Intercambio de llaves DHE O ECDHE
    3. El cliente hace el proceso como auntenticar al servidor, derivar la llave y empezar a enviar datos cifrados.
    4. TLS solo autentica el servidor, el cliente no envia un certificado para autenticarse.
    5. Una sesión puede tener varias llaves simetricas.
      • Confidencialidad (transporte en si)
        • Llave emisor-receptor
        • Llave receptor-emisor
      • Autenticación/Integridad (MAC)
        • Llave emisor-receptor
        • Llave receptor-emisor
    6. Con DH o transporte RSA generas un PMS, que permite generar un master secret.
      • Con el PMS puedes tener un generador de llaves
      • Intercambiar hellos (nonces, certificados, lista de cipher suits)
      • Negociación de cihper suites
      • Autenticacion
      • Intercambio/derivación de llaves
      • ChangeCipherspec
      • Finish (comprobación de hash)
    7. Handshake TLS
      • Establecer identidad
      • Establecer llaves de sesion
        • DH
        • Transporte de llaves RSA
    8. Transferencia en masa (bulk):
      • Se transfieren los datos de interes (payload)
      • Esa transferencia se hace con metodos simetricos.
    9. Http
      • Es un protocolo peticion-respuesta
      • La cantidad de interacciones peticion-respuesta hay una sesion http es de una por sesion.
    10. MiM en TLS
      • Cliente manda su hello que incluye la lista de cipher suite soportados
      • Un tercero altera la lista de cipher suits dejando solo las debiles
      • La forma de mitigacion es verificar el finished del handshake el hash de todo lo que se ha transmitido.
      • Verificar certificados
      • Verificar identidad -> reto-respuesta
    11. La criptografia es segura siempre y cuando no se comprometan los secretos
    12. Tiempo promedio para detectar una brecha es de 6 meses a 1 year

4.10.3. Ventajas de TLS 1.3

  • No tiene ciphersuits debiles
    • Nada con RSA -> transporte RSA
    • Solo AEAD
  • Menor latencia
  • Heartbeats (latido): En un sistema distribuido no puedes saber si un nodo esta activo o inactivo, solo puedes comprobarlo haciendo una petición, el heartbeat es una forma de comprobar si un nodo sigue activo cada x tiempo.
